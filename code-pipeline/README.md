# code-pipeline

A DeepSeek Harness plugin for **one-click code standardization**: a sidebar panel with
the workspace code file tree, single / multi / select-all picking, and ten built-in
language presets that apply a consistent style to the files you pick.

> Status: v0.1.0, P0 languages only. Anything outside the ten languages below is
> listed with a `跳过` badge and is never modified.

## Install

The bundle is a linked local checkout, not a published npm package. Add it through
DeepSeek Harness's **Plugin Manager** with the link spec below; a linked directory is
used in place, so run `pnpm install` in the checkout first.

```
link:D:/05_Code/code-pipeline
```

The profile used for this checkout already has it installed and enabled
(`source: link:D:\05_Code\code-pipeline`). Then reload the GUI page once — the Client
half is injected into the boot graph at page load, so a newly installed bundle appears
only after a refresh.

## P0 presets

| Language | Preset | Engine | Depth | Rules | Config |
| --- | --- | --- | --- | --- | --- |
| Go | `go` | gofmt (WASM) | format | 10 (F4 / S5 / X1) | `presets/go.json` |
| TypeScript | `typescript` | Biome (WASM) | full | 9 (F3 / S5 / X1) | `presets/typescript.json` |
| JavaScript | `javascript` | Biome (WASM) | full | 8 (F3 / S4 / X1) | `presets/javascript.json` |
| Python | `python` | ruff format (WASM) | format | 9 (F5 / S4 / X0) | `presets/python.json` |
| HTML | `html` | Biome (WASM) | format | 6 (F5 / S0 / X1) | `presets/html.json` |
| Makefile | `makefile` | built-in text rules | text | 6 (F5 / S0 / X1) | `presets/makefile.json` |
| CSS | `css` | Biome (WASM) | format | 5 (F4 / S0 / X1) | `presets/css.json` |
| C++ | `cpp` | clang-format (WASM) | format | 5 (F3 / S1 / X1) | `presets/cpp.json` |
| Shell | `shell` | shfmt (WASM) | format | 5 (F2 / S2 / X1) | `presets/shell.json` |
| PowerShell | `powershell` | built-in text rules | text | 7 (F5 / S1 / X1) | `presets/powershell.json` |

Rule classes: **F** format · **S** style · **X** capability note. The class says what a
rule is about, not that it is enforced: only formatter output is written, TypeScript and
JavaScript additionally report Biome lint findings, and rules an engine cannot enforce
stay declared in the preset. Each rule records an intended handling (`fix: auto` 40,
`report` 21, `none` 9), a tier (`T1` official text, `T2` official tool default, `T3`
de-facto standard, `T0` local decision) and a source URL where one exists — the seven
`T0` rules deliberately have none; the preset data keeps the provenance even though the
panel does not render rule metadata today.

`depth` means what actually ran: `full` = formatted **and** lint diagnostics collected,
`format` = formatted only, `text` = whitespace rules only. A missing engine degrades a
language to `text` and the report marks it `degraded`.

## Use it from the panel

1. Open the left rail and choose **Code pipeline**.
2. Pick a workspace in the header when more than one is registered.
3. Expand folders, check files, or press **Select all** (code files with a preset only).
   The header shows `selected / selectable` at all times.
4. **Check** reports what would change and writes nothing. **Standardize** writes.

## Use it from a conversation

```
code_list_files        — inventory with language and support status
code_standardize       — mode: "report" | "fix", paths: [...] or all: true
```

## Configuration

There is no Plugin Manager form for this plugin: DSH 0.2.2's custom config page
needs the `schemastery` dependency, which this linked package cannot resolve.
Configure the loader row in the profile's `cordis.patch.yml` instead; the panel
shows the effective limits and any configuration warnings in its status strip.

```yaml
- id: code-pipeline
  name: dsh-code-pipeline
  config:
    maxFiles: 4000          # 100..20000, default 4000
    maxBytes: 2097152       # 65536..8388608, default 2 MiB per file
```

Out-of-range or invalid values are clamped or fall back to the defaults with a
visible warning; they never block activation.

## Security model

- The plugin's three HTTP routes first apply the host Connection service's
  Host/Origin/credential fence: cross-site requests are refused with 403, no
  browser credential yields 401, and a missing Connection service fails closed
  with 503. Same-origin panel requests are unaffected.
- HTTP roots must be registered workspaces. Agent tools accept the registered
  workspaces or the Session working directory; an explicit `root` can no longer
  point at an arbitrary directory.
- Runtime runs reuse the scan rules: skipped dependency directories, ignored
  files, oversized files, non-UTF-8 sources and links that leave the root are
  never read or written even when named explicitly.

- Ignore files are read only from the workspace root (`.gitignore` and
  `.dsh-code-pipeline-ignore`); negation and `**` are not supported, and an
  unsupported pattern simply fails to exclude.

## Limitations

- Interface / function normalization is **out of scope**: only the rules listed in
  each preset file are applied, nothing beyond them.
- Makefile and PowerShell have no formatter engine; they get deterministic whitespace
  rules only.
- Binary files, dependency directories (`node_modules`, `dist`, `target`, `.venv`, …)
  and generated artifacts are excluded from the tree, so select-all cannot reach them.
- Style findings come from the engine's lint pass and are reported with file, line,
  rule and message; they are not rewritten because the engine classifies those fixes
  as unsafe. At most 40 findings are returned (errors first); per-file counts stay
  complete.
- `fix` mode has no undo; use git to review before writing. A file changed by an
  external editor between read and write is reported as `changed-since-read` and is
  not overwritten.
