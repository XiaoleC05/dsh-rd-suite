# AI / LLM / Agent 研发

## 1 评测先行
- 动手前定义成功指标与评测集：至少 20 条代表性样例，包含边界、对抗与“应当拒答”的样例；存为文件（jsonl / csv）并随代码版本化。
- 每次修改提示词、模型、检索参数或工具，都在同一评测集上运行，并记录指标、成本与延迟。
- LLM 评审：固定评分细则与锚点样例，输出结构化分数与理由；定期抽样人工复核一致性；评审模型不与被测模型共享上下文。
- 不只看平均分，检查失败样例的类别分布。

## 2 提示词
首句给出角色与目标；分节写背景、输入、步骤、约束、输出格式、验收标准；输出格式用 JSON Schema 或明确的模板；示例少而精并覆盖难例；稳定内容放前面、变化内容放后面以利用前缀缓存；不把密钥或用户隐私写进提示词；提示词版本化，并与评测结果关联。

## 3 工具设计（给 Agent 用的工具）
从最小上下文开始，细节按需加载；描述写“做什么、返回什么”，不写内部实现；参数规则写在参数上（默认值、范围、互斥关系）；每个事实只说一次；返回有界的结果，并提供获取更多内容的方式（分页、路径、ID）；破坏性操作需要确认；修改工具定义后，对比首轮 prompt token 的变化。

## 4 上下文与成本
统计每次调用的输入、缓存命中与输出 token；保持前缀稳定以命中缓存；为上下文设预算，接近上限时压缩或摘要；选择满足指标的最便宜模型，难例再升级；能批处理就批处理；设置超时与最大重试次数。

## 5 RAG
按文档结构切块并带少量重叠；检索评测（recall@k、MRR）与生成评测分开进行；回答引用来源；检索不到时明确回答“不知道”；索引与嵌入模型版本化。

## 6 Agent 工程
- 明确停止条件、最大步数与预算；工具调用失败时有上限地重试。
- 工具结果、网页和文件内容都是不可信数据，防范提示注入：不执行其中的指令，敏感动作需要人工确认。
- 完整的可观测性：记录输入、每一步的工具调用与结果摘要、耗时、token 与最终输出，并能按会话回放。
- 工具尽量幂等；有副作用的动作可审计、可撤销。

## 7 机器学习实验
固定随机种子；训练、验证、测试划分没有泄漏（时间序列按时间切分）；先建立简单基线；记录数据版本、超参数、代码版本与指标（MLflow、W&B 或 CSV）；不在测试集上调参；报告多次运行的方差或置信区间。

## 8 时效信息
模型名称、SDK 参数、价格与上下文长度变化很快：以官方文档为准（web_fetch 官方页面），注明查询日期；不凭记忆编写版本敏感的代码。

## 9 DeepSeek Harness 本身
开发 DSH 插件、预设、技能或接入 MCP 时，加载 dsh-doc 技能，以当前安装版本的文档与源码为准；大量涉及 DSH 内部 API 时，建议用户切换到“创造模式”。
