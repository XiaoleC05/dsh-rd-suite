# 文案与文档（rd-copy）

模式仓库 = 本技能 Base directory 的上两级目录。检查脚本在 `<模式仓库>/scripts/aigc-check.mjs`，命令的 workdir 设为 <模式仓库>，路径写绝对路径。

## 发布说明

面向用户的发布说明四段（一句话变化 / 你会遇到什么不同 / 需要你做什么 / 已知问题）：见 `references/release-notes.md`。草稿用 `node scripts/release-notes.mjs` 从 CHANGELOG 生成，占位段落需要人补。

## 对照示例

六组 before/after（README 简介 / 变更日志 / PR 描述 / 错误提示 / 提交信息 / 对外公告）：见 `references/before-after.md`。每组「改后」都由 `scripts/aigc-check.mjs` 校验过零套话且 90 分以上，测试会重跑一遍。

## 1 何时用

写或改任何一段会被别人读的文字：README、设计文档、使用说明、公告、邮件、PR 描述、提交信息正文、CHANGELOG、落地页文案。规则不适用于代码注释里的语法说明与机器可读字段。页面结构与版式交给 rd-web，本技能只管文字本身。

## 2 去 AI 味

写的时候就按这四条做，不靠事后润色：

1. **结论先行，段落短**。第一句给结论或结果，后面才是条件与过程。一段不超过 4 行；能用一句说清就别写三句。
2. **句长要有起伏**。长短句混排：一句 8 个字，下一句可以是 40 个字。连续 5 句长度相近就是模板腔。
3. **给具体的东西**。换成能核对的数字、文件名、命令、时间点、失败现象。写不出具体内容，说明这段还没想清楚，删掉比糊上形容词好。
4. **去套话**。禁用或替换：赋能、一站式、全方位、全面提升、极大地、显著地、深刻地、助力、颠覆、无缝、极致、领先、世界一流、不容忽视、至关重要、必不可少、众所周知、毋庸置疑、不难发现、值得注意的、在当今、随着……的快速发展、综上所述、总的来说、由此可见。第一句不要用「在当今」「随着」「众所周知」起手。
5. **少用连接词当路标**。首先／其次／再次／最后／总之／换言之／与此同时／更重要的是：一段里最多一个，能删就删；先后关系靠内容本身表达，不靠编号词。
6. **标点与格式**。中文用中文标点；一句话里不要连用两个破折号插入语；加粗只标真正的重点，一段最多一处；不要用 emoji 代替论证。

## 2.1 结构型痕迹（比用词更难改）

这几条来自 humanizer 的分类，换同义词消不掉，要改句子结构。脚本会直接报出编号对应的痕迹。

| 痕迹 | 长什么样 | 怎么改 |
|---|---|---|
| 不是 X 而是 Y | 「这不是速度问题，而是流程问题」「不仅仅是工具，更是方法」 | 直接说结论；只有读者真持有相反看法时才保留对比 |
| 三连并列 | 三个结构相同的短语排成队，删掉两个意思不变 | 留最有信息量的那一项，其余删掉或合并 |
| 破折号泛滥 | 一段里两三个「——」当插入语 | 拆成两句，或改成冒号、括号 |
| 行首加粗标签 | 每段都以 **要点**： 开头 | 加粗只留结论；正文里的标签去掉 |
| 拔高收尾 | 「归根结底」「正因如此」「这一切都」收尾 | 最后一段给事实、命令或下一步 |
| 聊天残留 | 「希望这对你有帮助」「如有其他问题」 | 整句删掉，交付物不是对话 |
## 3 AIGC 自检

改完先跑脚本，再人工看四项：

```
node scripts/aigc-check.mjs <文件...> --min-score 80
```

脚本给 0–100 的「人味分」，并列出套话、连接词、英文词藻、模板开头、重复片段、句长变异系数。交付前要求：**每个文件 ≥ 80 分**；低于 80 就按命中项改写后重跑。

人工四项（脚本抓不到的）：
- 有没有一句话是「换个说法也对」的空话？有就删。
- 每个结论后面有没有可核对的依据（数字、命令、链接、文件路径）？
- 段落顺序是不是「结论 → 依据 → 边界」？不是就调。
- 读第一段，能不能猜出这是谁写的、给谁看的？猜不出，说明还没有作者视角。

## 3.1 项目自定义禁用词

项目有自己的黑话或品牌词时，写一个词表文件（每行一个词，# 开头是注释；也接受 JSON 数组），运行时带上：

`
node scripts/aigc-check.mjs <文件...> --banned path/to/banned-words.txt
`

自定义词与内置表合并、自动去重；命中同样计入「套话」并按次数扣分。词表放在项目里随仓库走，不要写进本技能。
## 3.2 英文文案的信号

自检对英文也生效，重点看这几类：It's not just X, it's Y 的对举、In today's fast-paced world 式开场、Let's dive in 的过渡、Here's the thing 与 at the end of the day 的口头禅，以及一行里两个以上破折号。

改法只有一条：把形容词换成具体动词与数字。a robust, seamless platform 不如 p95 latency 0.6s under 42 concurrent runs。

## 4 降重

单文件看文风，多文件看重复：同一段话在 README 与设计文档里各写一遍，读者读到第二遍就烦。

```
node scripts/dup-check.mjs README.md docs/*.md
```

按空行切段、跳过标题列表代码块，归一化后比对；有重复返回 1 并列出所在文件与行号。改法是留一处、另一处改成一句话引用。

## 5 交付前清单

1. 脚本 `--min-score 80` 通过。
2. 没有第 2 节禁用清单里的词；模板化开头为 0。
3. 每个数字都能指到来源；指不到的数字删掉或标「估计」。
4. 标题、术语、命令格式与项目其他文档一致（同一概念只用一个词）。
5. 报告里写明检查命令与分数，例如「`node scripts/aigc-check.mjs README.md` → 100 分」。
