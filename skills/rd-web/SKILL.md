# 网站与前端研发

## 1 开工前确认（写进规格卡）
目标用户与使用场景；页面唯一的主转化动作（注册、下载、购买、预约、联系）；品牌语气与参考站点；技术栈与部署目标（纯静态 / React / Next.js / Vue / Astro 等）；已有素材（Logo、配色、截图、真实数据、用户评价）；需要支持的设备与浏览器。
能从仓库或用户消息得到的直接采用；其余只把影响结果的用户决策并入规格卡的那一次 ask_user_question（最多 3 问），其他按合理默认写成“假设”。
缺少真实素材时使用明显的占位内容，并在交付报告中列出待替换清单；禁止编造数据、客户 Logo、用户评价或认证标志。

## 2 落地页结构（按需取舍，顺序可调）
1. 首屏：价值主张标题 + 一句副标题 + 主 CTA（可配产品截图或演示）。
2. 痛点与场景：目标用户现在遇到的问题。
3. 方案与核心功能：3–5 项，每项写成用户收益。
4. 证据：数据、案例、评价、合作方（必须真实可查）。
5. 使用方式：约 3 步的流程。
6. 定价或方案对比（如适用）。
7. FAQ：回应价格、安全、迁移、售后等顾虑。
8. 收尾 CTA：再次给出主转化动作。
新写或重写页面文案之前，先 read 本技能目录下的 references/landing-copy.md 并按其执行。

## 3 工程标准
- 语义化 HTML：只有一个 h1，标题层级不跳级；使用 header / nav / main / footer；按钮用 button，跳转用 a。
- 响应式：移动优先；检查 360、768、1280 三档宽度；不出现横向滚动；点击目标不小于 44×44 px。
- 可访问性（WCAG 2.2 AA）：正文对比度 ≥ 4.5:1；图片有 alt（装饰图用 alt=""）；表单控件有 label；全部操作可用键盘完成且焦点可见；html 设置 lang；尊重 prefers-reduced-motion。
- 性能预算：LCP < 2.5 s、CLS < 0.1、INP < 200 ms；图片用 WebP / AVIF 并声明宽高，首屏以外懒加载；首屏关键 CSS 优先；不为小功能引入大依赖；字体最多 2 个家族并设置 font-display: swap。
- SEO：title ≤ 60 字符；meta description 70–160 字符；唯一的 canonical；Open Graph 与分享图；robots.txt 与 sitemap.xml；适用时加结构化数据。
- 安全与合规：target=_blank 的外链加 rel="noopener noreferrer"；表单前后端都校验；前端不放密钥；收集个人信息时提供隐私政策链接。
- 设计质量：统一的间距与字号刻度；一个主色加中性色；清晰的视觉层级；内容优先于装饰；“渐变大标题 + 三列图标卡片 + 通用插画”这类模板化组合必须有理由。
- 组件：沿用项目已有的组件库与样式方案，不混用多套 UI 库。

## 4 验证（每项给出证据）
1. 构建或类型检查通过（如 npm run build）。
2. 用 run_in_background 本地启动，请求页面返回 200，服务端日志无报错；浏览器控制台只在有 Playwright 时检查，否则列为未验证。
3. 项目中有 Playwright 时，在 360、768、1280 宽度截图并用 read_image 检查；read_image 报 IMAGE_UNSUPPORTED_MODEL 时改用 DOM 断言（scrollWidth ≤ innerWidth、关键元素可见），并写明未做视觉检查；没有 Playwright 时说明，并给出用户可执行的检查步骤。
4. 链接与表单可用；按 references/frontend-checklist.md 完成上线前检查。
5. 交付报告附上：访问方式、截图路径、待替换素材清单、未完成的检查项。
