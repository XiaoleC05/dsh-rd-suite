# 子代理简报模板

子代理**不共享本会话的上下文**：它看不到你刚读过的文件、刚做的判断、刚踩的坑。
所以简报必须自包含，返回必须可核对——否则拿回来的东西只能靠再问一轮补齐。

## 统一返回格式

不论哪种模板，返回都按这四栏写，缺一栏就退回重做。

```
结论：一句话说清结果（成立 / 不成立 / 需要更多信息）
证据：命令、文件行号或输出片段，每条结论至少一条证据
未验证：这次没覆盖的部分，以及为什么没覆盖
建议：下一步该做什么；没有就给「无」
```

「未验证」是四栏里最容易被删掉的一栏，也是最该留的：它决定了别人敢不敢直接把结论当真。

## 一、代码审查

```
任务：审查 SAMPLE_FILES 的改动，只报会导致错误行为或数据损坏的问题。
输入：SAMPLE_FILES 的完整内容；任务背景：MODULE_PURPOSE。
约束：不评论风格与命名；不确定的问题必须标注「待确认」，不要下断言。
返回：按统一返回格式写，结论限一句话，证据给出文件与行号。
```

## 二、资料侦察

```
任务：查明 QUESTION，只需要能直接引用的事实与出处。
输入：可用的检索范围：SEARCH_SCOPE。
约束：区分「文档写明」与「你的推断」；推断必须标注来源链。
返回：按统一返回格式写，证据里给 URL 或文件路径。
```

## 三、独立复核（验收用）

```
任务：复核 CLAIM 是否成立，默认立场是「它不成立」。
输入：CLAIM 的原文；可复现的验证命令：VERIFY_COMMAND。
约束：只认自己跑出来的结果；无法复现就判定为未验证，不要用「应该可以」代替。
返回：按统一返回格式写，结论只能是「成立 / 不成立 / 未验证」三者之一。
```

## 简报里不该出现的话

- 「尽量」「大概」「合适的话」——子代理无法判断你的容忍度；
- 「你知道的那个文件」——它不知道；
- 「把结果整理一下」——整理成什么形状，就是上面的四栏。
