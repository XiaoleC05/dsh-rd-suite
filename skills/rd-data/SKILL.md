# 数据工程与大数据

## 1 先确认数据契约（写进规格卡）
来源与访问方式；schema 与类型；主键与粒度（一行代表什么）；数据量级与增长；更新频率与时效要求；时区；空值语义；敏感字段（PII）；下游使用方。

## 2 正确性原则
- 幂等：重跑得到相同结果（按主键 merge / upsert，或按分区覆盖写），禁止无条件 append。
- 增量与回填：明确水位线字段；回填可按时间范围重放。
- 时间统一以 UTC 存储，展示层再转时区。
- Join 前后核对行数，警惕一对多造成的行数膨胀；写明去重规则。
- 指标口径写在代码注释或文档中（去重计数还是总数、是否含退款等）。

## 3 SQL 规范
显式列名，不用 SELECT *；复杂查询用命名的 CTE 分步；参数化查询，禁止拼接字符串；先在 LIMIT 或采样上验证；DELETE / UPDATE 先用相同条件 SELECT COUNT 并在报告中写明影响行数；无 WHERE，或针对共享库、生产库时，按宪章 §8 先征得同意；不在生产库上试验；大表注意索引与分区裁剪；关键字大写，一行一列。

## 4 pandas / polars / Spark
- 向量化运算，不逐行循环（大数据禁止 iterrows）；显式指定 dtype；避免链式赋值（用 .loc 或 assign）。
- 大文件：polars 用 scan_* 惰性计算；分块读取；只读需要的列；先估算内存。
- Spark：不把大数据 collect 到 driver；注意数据倾斜与 shuffle；合理分区与文件大小，避免小文件。
- 打印行数、列数与关键统计，而不是打印整张表。

## 5 数据质量校验（每个管道至少包含）
行数在预期范围内；主键唯一；关键列非空；取值范围与枚举合法；外键参照完整；与上次运行相比分布没有异常漂移。校验失败时中止写入并报告。

## 6 可复现
固定随机种子；记录依赖版本、数据快照或查询时间；分析过程脚本化，notebook 中的结论要落到脚本或文档；输出文件注明生成时间与来源。

## 7 性能
先测量再优化（记录耗时与数据量）；优先减少读取量（列裁剪、谓词下推、分区裁剪），再考虑并行度与缓存。

## 8 隐私与安全
PII 先脱敏或哈希再分析；不把真实数据粘贴进对话、日志或提交到仓库；示例与测试使用合成数据；连接串与密钥从环境变量读取。

## 9 验证与交付
小样本跑通 → 质量断言通过 → 全量运行。交付报告写明输入与输出行数、校验结果、耗时、产出位置与口径说明。
