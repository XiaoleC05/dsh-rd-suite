# 测试、调试与验证

## 1 选择验证方式（最小而充分）
| 改动类型 | 首选验证 |
|---|---|
| 纯函数、业务逻辑 | 单元测试 |
| API、服务 | 集成测试，或实际调用（Invoke-WebRequest / curl）检查状态码与响应体 |
| 前端页面 | 构建 + 本地启动 + 页面检查（截图或 DOM 断言），见 rd-web |
| 脚本、CLI | 用样例输入实际运行，检查输出与退出码 |
| 配置、基础设施 | 官方校验命令（--dry-run、validate、lint） |
| 数据处理 | 小样本运行 + 数据断言，见 rd-data |
先运行与改动直接相关的测试，时间允许时再运行全量。

## 2 缺陷修复：系统化调试
1. 复现：写一个失败的测试或最小复现脚本，确认看到同样的错误。没有复现不修。
2. 定位：读错误栈与日志；缩小范围（二分、隔离、打印关键变量）；一次只改变一个因素。
3. 根因：用一句话说明为什么出错，而不只是哪里出错。
4. 修复：修根因，不掩盖症状（不 catch 后忽略、不用 sleep 绕过竞态、不放宽断言）。
5. 回归：刚才失败的测试变绿，相关测试套件全部通过。
同一问题连续 3 个假设失败时停下：总结已排除的可能与证据，换思路或询问用户。

## 3 测试编写规范
- 一个需求至少一个测试，测试名描述行为：`test_<行为>_<条件>_<期望>` 或 `it('<条件>时<行为>')`。
- 断言可观察的行为（返回值、输出、状态变化），不断言实现细节。
- 覆盖边界：空输入、极值、非法输入、错误路径，以及适用时的并发与重入。
- 确定性：固定随机种子，注入时间与随机源；不依赖执行顺序；不访问真实外部服务（用 fake、mock 或本地容器）；临时文件放在临时目录并清理。
- mock 只替换边界依赖，不 mock 被测对象本身。
- 禁止为了通过而修改期望值、删除测试或加 skip；只有规格确实改变时才改，并在报告中说明。
- 沿用项目已有的测试框架与目录结构，不新引入测试框架。

## 4 在 Windows / pwsh 中运行
- 用项目定义的命令：`npm test`、`pnpm test`、`pytest -q`、`go test ./...`、`dotnet test`、`mvn -q test`、`cargo test`。
- 精简输出：`pytest -q --tb=short`；`vitest run --reporter=dot`；`jest --silent`；`go test ./...`。不用管道截取尾部：输出超长时工具会保留尾部并给出完整输出文件。
- 预计超过 2 分钟：前台运行并设 `timeoutMs: 600000`；被转入后台时用 `job_output`（`wait: true, timeout_ms: 600000`）等待一次，不用默认 30 秒反复等待，不重复启动同一套件。
- 退出码非 0 即失败；输出被截断时，到给出的完整输出文件里 grep 失败用例。
- 需要端口与服务时：`run_in_background` 启动 → `job_output`（`wait: true, timeout_ms: 15000`）等到监听日志 → 发请求验证 → 交付前 job_kill。

## 5 证据格式
| AC | 验证方式（命令或操作） | 结果（通过 / 失败 + 一行关键输出） |
无法运行的项写“未验证：原因”，并给出用户可以自己执行的命令。

## 6 不稳定测试（flaky）
失败后原样重跑一次；两次结果不一致则记录为 flaky 并在报告中说明，不靠重跑掩盖；能定位原因（时序、共享状态、网络）就修复。

## 7 覆盖率
覆盖率不是目标；新增或修改的关键路径与每个缺陷修复都必须有测试。项目设定了覆盖率门槛时不得低于门槛。
