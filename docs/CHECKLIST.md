# 横向检查清单（每 10 轮）

脚本能算的交给脚本，算不了的靠人看一眼。跑法：

```
node scripts/preflight.mjs        # 六道交付门禁一次跑完
node scripts/health.mjs --fail-on-drift
node scripts/health.mjs --row    # 直接输出下面表格的新行
```

只要出现术语漂移或打包缺口就返回 1，可以直接当门禁用。

## 体检脚本覆盖的六项

| 项 | 指标 | 判断标准 |
|---|---|---|
| 宪章体积 | prefix 字符数 | ≤ 5000；超过就删重复表述，不加新规则 |
| 技能 | 数量与最大正文 | 单个 ≤ 6000 字符；最大那个如果连着两期没被改过，考虑合并 |
| 测试 | 文件数与用例数 | 用例数不下降；下降说明有轮次在删测试 |
| 文档 | AIGC 分数 | 每份 ≥ 80 |
| 打包 | files 缺口 | 必须为空 |
| 术语 | 旧称命中 | 必须为空（历史文档豁免） |

## 脚本算不了、需要人看的四项

1. **术语一致性**：同一概念是否只用一个词（例如「关卡」与「门禁」不要混用）。抽查 README、DESIGN 与宪章各一段。
2. **文档与代码一致**：文档里写的命令、路径、状态码，抽 3 条到代码里核对。
3. **测试耗时**：`node --test` 的 duration 是否明显变长；单次超过 60 秒的用例要拆。
4. **宪章趋势**：把连续三期的宪章字符数写进本轮账本，涨了要能指出涨在哪条规则上。

## 检查之后

- 发现问题：当作本轮或下一轮的一个迭代来做，别顺手改到无关模块里。
- 没有发现问题：也要在本轮 Issue 里贴出脚本输出，证明这轮确实看过。
